# 对话元数据存档设计

## 目标

同一个 SillyTavern 对话在电脑与手机上共享同一份初星育成存档。SillyTavern 内嵌模式以当前对话的 `chat_metadata` 为主存储；独立网页和桥接不可用时继续使用浏览器 `localStorage`。

## 数据流

桥接扩展在向 iframe 发送角色卡与对话作用域时，同时发送当前对话保存的育成状态。前端收到握手前禁止向宿主回写；收到后按以下优先级处理：

1. 对话元数据已有存档：加载服务器存档，并刷新当前浏览器的本地副本。
2. 对话元数据没有存档、当前对话的本地副本已有担当：将本地副本迁移到对话元数据。
3. 两边都没有有效存档：保留空白选择界面，直到玩家首次选择担当后再创建服务器存档。

前端后续每次 `saveState()` 都先写本地副本，再通过 `postMessage` 请求桥接扩展写入当前对话元数据。桥接扩展校验消息来源与对话作用域，使用 SillyTavern 的 `saveMetadataDebounced()` 持久化。

## 对话切换

SillyTavern 触发 `CHAT_CHANGED` 后，桥接扩展重新发送该对话的角色、作用域和服务器存档。前端先关闭写入许可，再切换状态，避免旧对话的延迟保存覆盖新对话。

## 数据结构与兼容

元数据键使用 `hatsuboshi_produce_state_v1`，值包含版本、更新时间与完整前端状态。读取时只接受普通对象；缺失字段继续由现有 `ensureStateShape()` 和基础状态补齐。旧的 `localStorage` 存档不会删除，可作为迁移来源和离线后备。

## 验证

测试覆盖服务器存档优先、本地有效档迁移、空档不回写、不同对话作用域拒绝写入，以及独立模式继续使用本地存档。
