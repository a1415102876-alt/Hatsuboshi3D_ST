# 仓本千奈沙盒担当接入设计

日期：2026-07-15

## 1. 目标

把仓本千奈加入沙盒可选担当，并把 `E:/GKMS/KMCN/好感度剧情/1.txt` 至 `10.txt` 的前半段成长冲突压缩为可游玩的物色与三项个人课题。

本轮复用千奈现有的人物资料、数值预设、羁绊路线、校园日程、地图出现、立绘、头像和 Live 视频。8–10 话的 First Live 前后收束继续由通用沙盒 First Live 与现有 80/100 好感度路线承担，不在个人课题中重复结局。

## 2. 采用方案

采用“剧情 + 轻量条件”。

- 不只增加选择白名单和静态任务文本，否则千奈与其他担当没有玩法差异。
- 不重做完整十话专线，否则会和现有 `chinaBondRoutes`、好感度节点及 First Live 演出流程重复。
- 个人课题使用现有任务完成标签、地点上下文和委托结算事实，不增加第二套剧情状态机。

## 3. 任务包

新增任务包：

```text
仓本千奈
  scout_china
  china_main_01
  china_main_02
  china_main_03
```

`CHINA_PERSONAL_IDS` 固定为三个个人课题 ID，并加入 `SANDBOX_IDOL_QUEST_PACKS`。沙盒选择列表继续从任务包动态导出，因此不在 `app.js` 维护重复白名单。

### 3.1 担当物色：仓本千奈

物色地点使用 `world/campus-behavior.js` 已存在的千奈当天校园位置。

物色 Prompt 增加千奈专属事实：

- 制作人承认最初接触来自爷爷和学园长的委托；
- 不把走后门或唱跳才能写成签约理由；
- 制作人明确表示，即使没有委托和报酬，也愿意成为她的制作人；
- 千奈必须由本人决定是否接受。

千奈同意时先输出 `【初星任务完成】scout_china`。如果同一回复已经完整写出抛开委托后的本人认选，可紧接着输出 `【初星任务完成】china_main_01`。任务解析保持文本顺序：物色完成会先激活个人课题，随后同一回复可以合法完成第一项课题。若模型只输出物色标签，第一项课题保持 active，之后仍可在普通场景补完。

### 3.2 个人课题一：亲自选择

目标：让千奈从“接受爷爷安排的人”变成正式选择制作人的当事人。

完成条件：剧情同时具备以下事实并输出 `china_main_01` 完成标签：

1. 委托与报酬真相被说明；
2. 制作人给出不依赖家世的认选理由；
3. 千奈本人明确接受。

不得把她写成早已拥有出众唱跳实力，也不得把家世委托抹去。

### 3.3 个人课题二：不甘休的基础

目标：在入学末位、跟不上普通训练并倒下后，仍由千奈本人选择回到基础训练。

适用地点：`idol_classroom`、`gymnasium`、`playground`、`special_education`、`producer_classroom`。

完成条件：一次训练或复盘场景写出“落后或失败 → 确实想过放弃 → 仍回来继续普通基础课题”，并输出 `china_main_02` 完成标签。

本课题不绑定高属性、累计次数或体力阈值。它验证的是选择与剧情事实，不把千奈突然写成训练强者。

### 3.4 个人课题三：优势与成果

目标：承认家世、外表与教养是可用资源，同时确立“不把优待冒充唱跳实力”的使用边界，并拿出可核实的宣传成果。

任务状态增加两个布尔标记：

- `advantage_boundary_confirmed`
- `publicity_commission_completed`

边界标记可由剧情输出 `【初星任务标记】china_advantage_boundary` 设置。Prompt 要求千奈明确只在必要范围使用资源，并接受外表、礼仪和教养也是偶像工作能力的一部分。

宣传成果由前端权威结算：当前负责偶像是仓本千奈，且完成的委托满足以下任一条件时，在 `pass_low`、`pass` 或 `perfect` 档记录成果：

- 地点为 `photo_studio`；
- 委托标题或说明包含杂志、摄影、拍摄、宣传照、品牌视觉或模特语义。

`fail` 不记录成果。两项标记同时成立后，数值检查自动完成 `china_main_03`。AI 不能仅凭叙述伪造已完成的商业委托。

## 4. Prompt 接入

### 4.1 物色 Prompt

任务模块提供千奈物色补充块，`buildSandboxScoutExplorePrompt()` 在目标为仓本千奈时注入。通用 option、time、地点在场校验和签约收尾流程保持不变。

### 4.2 普通行动与地图 Prompt

`buildSandboxMainQuestPromptBlock()` 增加三项千奈课题：

- 第一项允许在物色后续或关系复盘中补完；
- 第二项按训练地点给出不同提示；
- 第三项显示边界确认与宣传成果的当前状态。

### 4.3 委托 Prompt

委托开场在当前担当为仓本千奈且委托属于宣传类时注入第三课题补充块。模型可输出边界标记，但委托成果只由 `applySideQuestTier()` 的实际档位写入。

## 5. 状态与迁移

`defaultTasksState()` 新增千奈物色与三个个人课题。`ensureTasksShape()` 通过现有 `MAIN_QUEST_META` 遍历自动补齐旧存档，并为 `china_main_03` 补齐两个布尔标记。

多担当规则沿用现有实现：

- 千奈确认后加入 `assignedIdols`；
- 千奈拥有独立数值、任务、First Live 和挑战档案；
- 切换当前负责偶像不会转移已接委托；
- 千奈委托只在千奈是当前负责偶像时结算她的个人课题。

旧存档不会自动把千奈视为已签约。已有千奈关系与人物数据继续保留。

## 6. UI 与提示

任务面板增加千奈物色和三项个人课题标题、冲突说明、进度提示与完成 Toast。

第三项进度显示：

```text
资源使用边界：已确认/未确认 · 宣传委托成果：已完成/未完成
```

不新增专用页面、弹窗或数值控件。

## 7. 测试

至少覆盖：

1. 千奈进入沙盒可选担当，任务包导出正确；
2. 千奈旧存档自动补齐任务和标记；
3. 完成 `scout_china` 只激活千奈个人课题，不激活其他偶像课题；
4. 同一回复按顺序完成 `scout_china` 与 `china_main_01`；
5. 千奈物色 Prompt 包含委托真相、本人选择和两个完成标签规则；
6. 第二课题只在合法训练语义下提示完成，不加入数值门槛；
7. 宣传委托非失败结算记录成果，普通委托和失败档不记录；
8. 只有边界与成果均成立时完成 `china_main_03`；
9. 任务面板、完成 Toast 和多担当候选包含千奈；
10. 现有偶像任务包、First Live、羁绊、多担当 ownership 与旧存档迁移无回归。

## 8. 明确不做

- 不新增千奈 8–10 话专用 First Live。
- 不重写现有 `chinaBondRoutes` 或好感度种子。
- 不增加家世、财产或爷爷影响力数值。
- 不让 AI 修改委托结算档位、奖励、数值或任务状态。
- 不加入 11–37 话素材；本轮范围保持为用户指定的 1–10 话。
