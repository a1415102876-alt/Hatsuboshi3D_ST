# N.I.A 日终公寓阶段设计

## 目标

在 N.I.A 五日固定日程中，每个计划日完成全部结算后进入一个从 22:00 开始的晚间阶段。晚间阶段完整复用沙盒模式现有的制作人公寓界面与交互，但日期、时钟和次日推进必须由 N.I.A 状态管理，不得修改沙盒模式的日期、行动轮次或世界日更状态。

## 范围

### 包含

- 普通训练、休息、外出、陪同训练、制作人工作、线上直播、广播与初星圈营业完成后的日终入口。
- 现有回家选择、制作人公寓舞台、同行偶像、聊天、亲密互动、邀约、来访、手机、今日总结、立绘衣柜和睡觉功能。
- N.I.A 独立的晚间日期、时钟、同行偶像与恢复状态。
- 第五日晚间结束后开放第六日第一轮试镜。
- 页面刷新后的晚间恢复。

### 不包含

- 修改沙盒公寓的现有玩法规则。
- 为 N.I.A 复制第二套公寓 DOM、样式或聊天协议。
- 在 N.I.A 晚间重新开放校园地图。
- 为不同 N.I.A 日程推导不同的结束时间；所有日终公寓固定从 22:00 开始。

## 核心流程

1. 当前 N.I.A 计划日的最后一个业务流程完成结算。
2. 原有流程正常写入属性、粉丝、公开形象及其他奖励，并把 `training.actionIndex` 推进到下一项计划。
3. 系统根据刚完成的计划日创建或激活对应的 `nia.evening`，时间设为 22:00。
4. 若有必须先完成的强制剧情或正在播放的结算剧情，先完成该剧情；随后恢复日终回家入口。
5. 玩家选择独自回家，或在满足现有好感条件时带偶像同行。
6. 玩家在现有制作人公寓中自由使用完整功能。
7. 点击睡觉后，仅完成当前 `nia.evening`，不得再次增加 `training.actionIndex`。
8. 系统返回 N.I.A 平板并显示下一项计划；第五日晚间完成后显示第六日试镜入口。

## 状态模型

在 N.I.A 状态中新增：

```js
evening: {
  status: "idle" | "active" | "completed",
  dayIndex: 0,
  clockMinutes: 1320,
  companionIdol: "",
  startedAt: 0,
  completedAt: 0
}
```

字段含义：

- `status`：当前晚间是否尚未开始、正在进行或已经睡觉完成。
- `dayIndex`：刚完成的 N.I.A 计划日索引，而非已推进后的 `training.actionIndex`。
- `clockMinutes`：N.I.A 公寓时钟，激活时固定为 1320，即 22:00。
- `companionIdol`：本晚同行回家的偶像；独自回家时为空。
- `startedAt`、`completedAt`：用于恢复、幂等和诊断的时间戳。

旧存档缺少该字段时归一化为 `idle`。只有完成新的 N.I.A 计划日时才激活晚间，不得让已经推进过的旧存档倒退补放所有历史夜晚。

## 公寓适配层

现有公寓继续作为唯一 UI 和互动实现。新增少量模式感知接口，集中决定当前公寓的状态来源：

- 当前是否处于 N.I.A 晚间。
- 当前公寓日期标签。
- 当前公寓时钟。
- 当前同行偶像的读取与写入。
- 公寓互动推进时间。
- 睡觉后的模式专属处理。

当 N.I.A 晚间激活时，上述接口读写 `nia.evening`；否则维持原有 `freeMode` 行为。公寓内部不应散布大量 `launchMode === "nia"` 分支。

N.I.A 时间推进只更新 `nia.evening.clockMinutes`。它不得调用沙盒的次日推进、世界日更、校园任务同步、自由模式在场角色刷新或导演日更逻辑。

## 入口与结束

### 进入晚间

所有能够最终推进 N.I.A `training.actionIndex` 的完成路径，在结算成功后调用同一个日终协调函数。协调函数必须幂等，并使用“刚完成日索引”防止同一次结算重复激活晚间。

日终激活后隐藏 N.I.A 平板，显示现有回家选择。由于时间已经是 22:00，不提供“返回校园”或“再晚一点”。

### 睡觉

N.I.A 晚间点击睡觉时：

- 清除同行偶像和公寓临时交互状态。
- 将晚间标记为 `completed`。
- 不修改粉丝、属性或 `training.actionIndex`。
- 不运行沙盒世界日更。
- 保存并返回 N.I.A 平板。
- 根据已经推进的 `training.actionIndex` 展示下一日或试镜入口。

## 强制剧情与恢复优先级

恢复顺序遵循“已经开始的流程不能被新入口打断”：

1. 正在生成、播放或等待重试的主模型剧情。
2. 未完成的试镜赛后复盘、5000 粉丝里程碑等强制剧情。
3. 已激活但尚未睡觉的 N.I.A 晚间公寓。
4. 下一项 N.I.A 日程。

日程结算可以先把晚间写为 `active`，再启动强制剧情。强制剧情结束后通过统一 N.I.A 恢复路由进入公寓。刷新时同样根据持久化状态恢复，不重复发放奖励或推进日程。

## 完整公寓功能

N.I.A 晚间保留现有公寓功能及其原有解锁条件：

- 手机和初星圈。
- 今日总结。
- 立绘衣柜。
- 同行偶像立绘及聊天。
- 满好感亲密互动和邀约。
- 符合条件的主动来访。
- 睡觉。

依赖沙盒世界状态的可选内容在没有有效候选时保持隐藏或禁用，不为 N.I.A 伪造候选。角色资料和外观配置继续使用项目现有的共享数据。

## N.I.A 好感度来源

制作人公寓虽然复用沙盒模式的界面和互动流程，但必须按当前游戏模式选择关系数据源：

- N.I.A 晚间只允许当前担当偶像参与同行与公寓互动，并以育成状态的 `state.trust` 作为唯一权威好感度。
- N.I.A 的同行资格、满好感亲密解锁、邀约校验和提示词中的当前好感度全部读取 `state.trust`，不得读取 `state.freeMode.relationships`。
- N.I.A 公寓聊天若收到合法的担当关系增量，只将其按每轮 `-5` 至 `+5` 的范围结算到 `state.trust`，并限制在 `0` 至 `100`；不得写入沙盒关系表，也不得更新非担当偶像或 NPC。
- 沙盒公寓保持原有多偶像与 NPC 独立关系表、`relationship_update` 解析和结算逻辑。
- 模式分流必须集中在共享的公寓关系访问与结算边界，避免同行按钮、亲密按钮、提示词和最终写入各自判断而再次产生不一致。

## UI 文案

- 时钟：`N.I.A Day N · 22:00`，随后按 N.I.A 公寓互动耗时更新。
- 提示：`今天的 N.I.A 日程已经结束。可以整理今天的事，或休息进入下一日。`
- 睡觉按钮说明：`结束今天，进入下一项 N.I.A 日程。`
- 第五日睡觉后的提示：`五日计划已完成，第一轮试镜即将开始。`

## 错误处理

- 重复调用日终协调函数不得重置已经进行中的晚间时钟或同行选择。
- 重复点击睡觉不得再次推进日程。
- 存档中的晚间日索引与已完成计划不一致时，以最近一次合法完成的计划日为准；无法确认时不自动激活。
- 主模型请求未完成时禁止睡觉或切换流程，并沿用现有重试机制。

## 测试策略

### 状态单元测试

- 旧存档正确获得默认晚间状态。
- 每个计划日只激活一次晚间。
- 睡觉完成晚间但不增加 `training.actionIndex`。
- 第五日晚间完成后保留试镜入口条件。
- N.I.A 时间推进不修改 `freeMode` 日期和时钟。

### 流程测试

- 普通训练、休息和外出结算进入晚间。
- 陪同训练的校内自由活动结束后进入晚间。
- 制作人工作完成后进入晚间。
- 线上直播、广播、初星圈营业完成后进入晚间。
- 强制剧情结束后恢复晚间公寓。
- 刷新恢复回家选择或已进入的公寓。
- N.I.A 同行、亲密解锁和提示词只读取 `state.trust`，即使沙盒关系表中存在不同数值也不受影响。
- N.I.A 公寓聊天只更新担当的 `state.trust`；沙盒公寓仍只更新独立关系表。

### UI 回归测试

- 同一套公寓 DOM 在沙盒和 N.I.A 中均可显示。
- N.I.A 显示 N.I.A 日期和时间。
- N.I.A 晚间隐藏返回校园入口。
- 手机、总结、衣柜、邀约、来访、同行互动和睡觉控件保持可用。
- 沙盒公寓现有测试继续通过。

## 2026-08-05 交互修订：育成界面入口

- N.I.A 日程结算和结算 VN 播放完成后关闭 VN，返回育成主界面，不自动打开回家选择。
- `nia.evening.status === "active"` 且尚未进入公寓时，育成界面的行动区只显示一个“回公寓”按钮；下一日行动和第六日试镜入口暂时隐藏。
- 点击“回公寓”后才打开现有回家选择，可选择独自回家或满足条件时带偶像同行。
- 刷新恢复到尚未回家的 N.I.A 晚间时，同样显示育成主界面的“回公寓”按钮；已经进入公寓时仍直接恢复公寓。
- N.I.A 晚间睡觉后关闭公寓并回到育成主界面，显示下一日行动；第五日晚显示第六日试镜入口。
- 睡觉不得重新显示保留旧投影的 N.I.A 制作人工作平板。
