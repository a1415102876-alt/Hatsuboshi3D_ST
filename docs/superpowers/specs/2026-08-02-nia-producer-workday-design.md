# N.I.A 制作人工作日设计

## 目标

在正式 N.I.A 五日育成流程中实现“制作人工作”行动。玩家要在上午、下午、傍晚三个时段之间安排有限精力，通过企划管理、外部接洽、线上运营或陪同训练，为同一轮公开活动创造条件。系统强调制作人与偶像的共同成长，不把制作人工作做成独立数值菜单，也不把任务的解决办法预先写死。

首版以花海咲季第一轮企划为验证场景，但状态结构和 AI 契约必须允许后续偶像与轮次复用。

## 正式流程位置

- 继续复用 `state.nia.plan.days` 与现有 N.I.A 按日推进逻辑。
- 当前计划日类型为“制作人工作”时，育成界面的行动按钮进入工作日桌面，而不是直接结算行动。
- 工作日结束后才把 N.I.A 的 `training.actionIndex` 推进一次。
- 工作日不是独立测试页；它由正式宿主状态控制，并通过现有 N.I.A iframe 消息桥与主 API 通道工作。
- 工作日结束后返回正式育成界面，下一日继续按照已确认的五日计划推进。

## 一天结构

一天固定包含上午、下午、傍晚三个时段。系统先放入不可自由移动的外部预约，玩家安排剩余时段。玩家可以在每段结束后调整尚未开始的安排。

每个工作时段只调用一次主 API。调用前，前端必须先展示足以判断的资料和可选行动；调用后，AI 一次性生成执行过程、当前场景的明确收尾、客观回执和下一阶段资料。请求失败时保留玩家的安排与输入，不消耗时段。

工作日开始与结束各有一个不占时段的轻量叙事节点：

- 出发前，制作人与偶像确认当天各自要处理的事情。
- 最后一个时段的回复附带二人合流剧情，让重要工作结果回到二人关系和后续日程中。

这两个节点不增加主 API 调用次数。

## 待办组成

每天只显示二至三项待办，“陪同训练”常驻但不计入待办数量。

1. 核心待办：来自本轮企划和下一次正式营业的必要条件，始终只有一项。
2. 承接待办：由此前工作或剧情产生的后续事项。
3. 可选待办：改善后续营业条件、补充素材或降低风险。
4. 紧急待办：只在已有风险触发时出现，并替换可选待办，不增加第四项。

系统决定任务角色与优先级，AI补全具体对象、现场资料和叙事表达。AI不得无限追加任务。新问题默认进入后台待办池，到下一个制作人工作日出现；只有明确的即时危机可以成为紧急待办。

待办卡默认只显示任务名、类别图标、建议时段、截止时间和一句话目标。点开后才显示背景、限制、已有筹码、偶像边界和预期产物；不显示成功率或预判奖励。

首个工作日的任务与初始 `briefing` 由企划生成结果中的工作种子提供，不额外请求主 API。后续工作日由前端按照核心、承接、可选或紧急的优先级，从已保存任务池中选择二至三项。旧企划没有工作种子时，第一轮咲季使用本地兜底任务，其他情况使用当前计划日的目标和产物生成最小可执行任务，不能因存档版本较旧而卡住流程。

## 三类工作

### 企划与管理

在平板中比较候选活动、日程冲突、素材缺口和风险，通过排序、取舍与批注形成内部文件。常见产物包括拍摄方案、节目提案、素材清单、风险预案和日程调整案。

企划管理不直接取得外部许可，也不直接增加粉丝。需要与场地、企业或节目方交涉的事项必须派生为外部接洽。

### 外部接洽

查看对方需求、我方目标、偶像边界与可交换条件，玩家选择普通行动或自由提出谈判方案，AI生成接洽过程与具体条款。外部会面进入现有剧情层，并根据对象切换电视台、企业或活动现场背景。

建议投入两个时段的接洽任务包含“准备”和“正式执行”两个阶段；最低可只投入正式执行的一个时段。准备阶段的回执生成出演提案、调查或预案，并把对方的下一阶段反馈写入 `nextBriefing`。跳过准备不直接失败，但正式接洽时缺少相应信息和筹码。

### 线上运营

手机移动到桌面中央并打开 SNS 工作界面。玩家选择实际持有的素材、希望呈现的形象角度、发布语气及评论处理方针，也可以自由填写。AI返回公开内容、偶像反应、代表性网络反馈、形象变化和后续问题。

前端为发布类型提供基础粉丝范围；AI只能返回“平淡、正常、良好、热门”反响档位及基于剧情证据的理由，前端再换算受控的粉丝和舆论压力变化。普通线上发布不能获得正式营业级别的爆发增长。

危机公关不是第四类工作，而是附着在外部接洽或线上运营上的紧急状态。

## 陪同与自主训练

- 制作人工作日最多安排一个时段陪同训练。
- 完全不陪同：偶像获得一次稳定的基础训练成长，但不推进当前训练难题。
- 安排陪同训练：获得针对性成长，并推进企划主线中的具体困难。
- 如果玩家希望投入更多训练时间，应选择五日计划中的专门训练日。

偶像在制作人处理工作的时段默认自主训练。训练结果按一天结算一次，不能按三个无人陪同时段重复累计。

## 阶段数据流

每个任务阶段遵循同一条链路：

`初始资料 -> 玩家决策 -> 本段剧情与结果 -> 下一阶段资料`

任务生成或上一阶段回执必须提前提供本阶段的 `briefing`。因此前端不需要为了“让AI先出题”额外调用一次 API。阶段回复中的 `nextBriefing` 只能为明确的下一阶段提供资料，不能擅自完成下一任务或推进时间。

一次工作回执包含：

- 当前场景的完整收尾剧情；
- 工作结果摘要；
- 新增文件、素材、联系人或已确认条款；
- 客观工作履历；
- 下一阶段资料；
- 新的承接任务或风险变化；
- 最后时段的偶像合流片段。

前端控制时段、预约、期限、任务状态和所有受限数值。AI负责具体叙事、角色反应、条款文字与证据判断，不能擅自改变硬状态。

## 状态模型

在 `state.nia` 下增加独立的 `producerWork` 运行时，至少保存：

- 当前工作日、当前时段和工作日状态；
- 当日二至三项任务及任务池；
- 三时段安排、固定预约和已经完成的阶段；
- 玩家尚未提交的安排与决策；
- 文件、素材、联系人、条款和简短客观履历；
- 风险、承接任务与当前 API 请求租约；
- 已处理 operation ID，保证重试幂等。

旧存档缺少该字段时必须安全补默认值。N.I.A 以外模式不得读取或渲染制作人工作日状态。

## 第一轮咲季样例

首个制作人工作日提供以下验证组合：

- 核心：新人偶像综艺出演洽谈，建议两段、最低一段、正式会面固定预约。
- 可选：自律生活 Vlog 发布准备，占用一段。
- 动态承接：商店街 Vlog 取材方案，占用一段；它只形成内部方案，需要许可时再派生外部接洽。
- 常驻：陪同咲季训练，占用一段且每天最多一次。

三段无法清空所有事项，玩家必须决定把精力放在接洽准备、线上预热、取材方案还是陪同训练上。

第一轮五日的推荐因果结构是：

1. 制作人工作：争取机会并确定公开条件。
2. 陪同训练：解决节目条件暴露出的具体问题。
3. 外出：只固定心情调剂作用，地点、话题和行动当天由玩家决定。
4. 线上营业：使用此前实际取得的素材进行预热。
5. 正式营业：回收接洽、训练、外出和预热形成的证据链。

企划 AI 不得替玩家规划外出的具体地点或内容。

## 延期与截止

- 主动延期会保留任务并占用后续工作日的任务位。
- 错过可选任务会关闭机会，但不判定育成失败。
- 错过核心任务会关闭原机会，并生成条件较差的补救任务。
- 固定预约可以主动放弃，但前端必须在确认前显示既定后果。
- 信誉、联系人或机会变化由任务规则决定，AI只负责演绎，不临场决定严重程度。

N.I.A 不因一次工作失误形成死档。玩家需要在不完美条件下继续推进企划，但不能无成本撤销已经作出的外部承诺。

## 界面与转场

- 沿用现有 N.I.A 桌面、平板和手机，不增加抽象任务主菜单。
- 平板中央显示三段日程；右侧显示二至三项待办和常驻陪同训练。
- 固定预约预先落位，玩家通过按钮安排其余时段，不要求拖拽。
- 每段完成后回到桌面，当前日程格盖完成章，文件或消息落到桌面，未开始安排仍可修改。
- 企划管理留在平板；线上运营将手机移到中央；外部接洽和陪同训练进入现有剧情场景。
- 所有控件提供稳定尺寸、键盘操作和明确禁用状态；动态文字不得改变日程格和设备的整体布局。

## API 与失败恢复

- 每个时段只有一次主 API 请求，并继续复用当前主模型租约、request ID、turn ID、save scope 与 session epoch 校验。
- 工作请求使用独立 owner kind，不能与 N.I.A 企划、开场、营业或其他主模型请求串线。
- 解析结构化结果时选择回复中最后一个完整结果标签，忽略思考文本里较早出现的示例标签。
- 只有最终回复且请求租约匹配时才能提交回执和消耗时段。
- 格式错误、断线或过期回复只进入可重试状态；保留玩家决策，不结算、不推进时段。
- 结构化字段必须限制数组数量、文本长度和数值范围。

## 验收标准

- 正式 N.I.A 计划推进到“制作人工作”时能进入工作日桌面，并在完成三段后只推进一个计划日。
- 玩家能看到三段日程、固定预约、二至三项待办与陪同训练，并能调整尚未执行的安排。
- 两阶段任务能把前一阶段成果和 `nextBriefing` 传给后一阶段。
- 企划管理、外部接洽、线上运营和陪同训练使用各自对应的现有界面或剧情层。
- 每个时段只发送一次主 API 请求，失败重试不消耗时段。
- 工作结果能持久化为文件、素材、联系人、条款、履历、风险和承接任务。
- 最后一个时段包含与偶像合流的明确收尾，并把结果传给后续训练、外出或营业。
- 自主训练每天只结算一次；陪同训练每天最多一次。
- 非 N.I.A 模式、普通“初”育成和沙盒模式不发生回归。
