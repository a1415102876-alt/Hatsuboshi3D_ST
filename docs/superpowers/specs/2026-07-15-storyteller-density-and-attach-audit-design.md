# Storyteller 事件密度与 Attach 审计设计

## 目标

提高初星世界引擎每天可生成的事件总量，并让玩家能够在世界引擎中调整次日事件密度、检查当天生成的全部 Attach 事件。

本次同时修复沙盒首日使用静态世界池时没有建立 Storyteller Plan 的缺口。事件生成仍受玩家行动、地点、角色、冷却、重复和多样性规则限制；预算提高不代表每天强制触发固定数量的事件。

## 预算口径

Attach 与 Invite 继续共用 Storyteller Plan 的强度预算。预算按当前存档、当前日期、当前计划和事件强度统计，不按事件渠道拆分。

系统提供四种密度模式：

| 模式 | 轻微 | 中等 | 普通日合计 | 危机日重大上限 |
| --- | ---: | ---: | ---: | ---: |
| 较少 | 3 | 2 | 5 | 1 |
| 标准 | 4 | 3 | 7 | 1 |
| 较多 | 6 | 3 | 9 | 1 |
| 自定义 | 玩家设置 | 玩家设置 | 5 至 12 | 0 至 1 |

新存档和没有密度配置的旧存档默认使用“标准”。自定义模式下，轻微与中等预算均为非负整数，二者合计必须在 5 至 12 之间；重大预算只能是 0 或 1。

计划的 `pacing` 继续影响候选事件的合法性、强度选择顺序和重大事件开关，但不再把轻微与中等事件总预算压低到 5 以下。重大预算只在 `crisis_allowed` 计划中开放，其他节奏下固定为 0。因此标准模式普通日预算为 7，危机日最多为 8。

## 配置状态与生效时间

在当前存档的 `state.freeMode.world.storyteller` 下保存独立的事件密度配置。配置包含模式和自定义预算，不与次 API 设置或文风比例混用。

世界引擎设置页保存配置后立即持久化，但不修改当天已经提交的 Storyteller Plan。下一次建立新日期计划时读取最新配置并写入该计划的 `severityBudget`。当天页面继续以计划内预算为准，并显示“已保存，次日生效”。

这种设计不需要维护第二份当天活动预算：当前计划是当天事实，保存的密度配置是下一个计划的输入。刷新页面或重新进入存档后，两者都能恢复。

## 世界引擎设置页

在“高级设置”中新增“事件密度”区块：

- 使用分段选择控件提供“较少 / 标准 / 较多 / 自定义”。
- 选择固定档位时显示该档位的轻微、中等和危机日重大预算摘要。
- 选择“自定义”时显示轻微、中等、重大三个数字输入控件。
- 自定义轻微与中等合计小于 5 或大于 12 时禁止保存，并显示明确的范围提示。
- 保存成功后显示次日生效状态，不重建当天计划，也不触发 Director 或次 API 请求。

现有文风比例、次 API 和维护工具区块保持原行为。

## 今日事件与 Attach 审计

世界引擎“事件”页顶部新增今日预算摘要：

- 轻微、中等、重大各自显示“已用 / 总量”。
- 显示今日 Attach 与 Invite 的已生成数量。
- 预算使用量按当天同一计划下的当前候选和历史候选去重统计，避免当前候选进入历史后重复计数。
- 尚未结算的 Invite 也计入页面的“已生成”统计，使用户看到的数量与系统实际选中的候选一致。

事件页新增“今日 Attach 事件”列表，合并以下现有数据：

- `storyteller.pendingCandidate` 中当天、当前计划且 `channel === "attach"` 的候选；
- `storyteller.recentCandidates` 中当天、当前计划且 `channel === "attach"` 的候选；
- `storyteller.observations` 中与 `sourceTurnId` 对应的行动与时间信息。

列表按发生时间排序，并以 `incidentId` 去重。每条显示：

- 游戏内时间；
- 来源行动；
- 地点；
- 类别与强度；
- 事件骨架的玩家可读摘要；
- 参与角色；
- 文风；
- 状态。

状态统一映射为“待附着”“已附着到 Prompt”“叙事已完成”“已过期”。不得显示内部 Prompt、API Key、存档作用域、请求标识、租约标识或内部定义 ID。

当天没有 Attach 时，页面显示空状态，并结合 `lastCandidateReason` 与 `lastSelectionDiagnostic` 显示最近一次可公开的未生成原因，例如计划未建立、没有合法候选、冷却、重复或多样性限制。

本次不新增无限增长的完整事件日志。现有候选和观察记录的有界保留策略不变。

## 沙盒首日计划

首次完成沙盒邀请并进入校园、执行首日静态世界生成后，必须为当前日期和存档建立 Storyteller Plan。次 API 世界生成完成后的现有建计划路径保持不变。

建计划操作必须保持幂等：若当前日期已有已提交计划，不重复建立或覆盖。首日计划使用当前保存的事件密度配置；旧存档没有配置时使用“标准”。

## 兼容性与失败处理

- 旧存档缺少密度配置时规范化为“标准”，不改写当天已有计划。
- 旧计划继续按其原有 `severityBudget` 运行，直到次日生成新计划。
- 非法或损坏的自定义配置回退到“标准”。
- UI 保存校验失败时不修改已保存配置。
- 首日建计划失败时沿用现有 `lastPlanError` 和重试机制，不阻止玩家进入沙盒。
- 预算提高不绕过候选合法性、重大事件确认、重大事件冷却或多样性限制。

## 测试

自动化测试覆盖：

1. 新旧存档默认密度均规范化为“标准”。
2. 三个固定档位生成 5、7、9 个普通日预算。
3. 自定义预算只接受普通事件合计 5 至 12、重大 0 至 1。
4. 平静计划不会把普通事件总预算降到 5 以下。
5. 重大预算仅在 `crisis_allowed` 计划中生效。
6. 保存密度配置不修改当天计划，新配置在次日计划中生效。
7. 设置页正确渲染固定档、自定义输入、校验错误和次日生效提示。
8. 今日预算按强度和渠道统计当前候选与历史候选，并正确去重。
9. Attach 列表只包含当天当前计划的 Attach，按时间排序并覆盖四种状态。
10. Attach 列表不会泄露内部标识、存档作用域或 Prompt 内容。
11. 无 Attach 时显示经过公开映射的最近未生成原因。
12. 沙盒首日静态世界路径建立一次当前 Storyteller Plan，已有计划时不覆盖。
13. 次 API 世界生成、后续换日、Invite 收件箱和 Prompt 注入原有测试继续通过。

## 不在本次范围

- 不保证每天实际触发 5 个或更多事件。
- 不拆分 Attach 与 Invite 的独立预算。
- 不增加重大事件上限到 1 以上。
- 不修改事件目录、事件文本或候选合法性规则。
- 不实现跨多日的完整事件历史档案。
- 不包含已另行设计的沙盒启动次 API 设置页。
