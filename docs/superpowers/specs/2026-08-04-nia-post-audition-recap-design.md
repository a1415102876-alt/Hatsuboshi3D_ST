# N.I.A 试镜后复盘剧情设计

## 目标

第一轮试镜通过后增加一个独立的赛后复盘阶段。担当偶像离开舞台，在试镜会场后台候场区与制作人会合；两人围绕本场高光、已经兑现的训练与营业成果，以及仍需带入下一轮的短板进行一次角色化对话。

复盘不是第五段试镜，也不参与排名或奖励计算。它负责完成第一轮的关系与叙事收束，让玩家在看到第一名和数值奖励后，还能获得一次与担当偶像直接交流的机会。

## 完整流程

```text
第四段试镜结束
-> 显示第一名、分数与固定奖励
-> 玩家确认结果，前端立即结算粉丝和属性
-> 请求 AI 生成赛后复盘开场与三个回应选项
-> 播放偶像下台后与制作人会合的开场 VN
-> 显示三个 AI 动态选项和一个前端自由输入入口
-> 玩家选择或输入制作人回应
-> 请求 AI 生成后半段复盘对话
-> 播放完整收尾 VN
-> 标记第一轮复盘完成并返回 N.I.A 主界面
```

奖励先于复盘结算。复盘 API 失败只影响剧情生成，不得撤销已经获得的第一名、粉丝或属性，也不得在重试时再次发放奖励。

## 状态边界

在 audition runtime 内新增独立的 `postAudition` 子状态。它与四段试镜共用同一 `auditionId`，但不增加 `segmentIndex`，也不进入试镜排名轨迹。

合法状态固定如下：

- `idle`：尚未确认试镜结果。
- `generating_opening`：正在生成复盘开场和三个选项。
- `awaiting_choice`：开场已生成并播放完毕，等待玩家回应。
- `generating_resolution`：玩家回应已冻结，正在生成收尾。
- `playing_resolution`：收尾已生成，正在 VN 中播放。
- `retryable_failed`：当前请求中断或格式错误，可重试失败阶段。
- `completed`：收尾 VN 已经播放到最后一页，复盘完整结束。

`progressionApplied` 继续只表示试镜奖励已经应用。`postAudition.status === "completed"` 单独表示赛后复盘完成。只有两者同时满足，第一轮才在 N.I.A 主界面显示为完整结束。

## 持久化数据

`postAudition` 至少保存：

```json
{
  "status": "idle",
  "openingStory": "",
  "options": [],
  "selectedResponse": "",
  "selectedResponseSource": "",
  "resolutionStory": "",
  "recapSummary": "",
  "activeRequest": null,
  "retryPhase": "",
  "lastError": "",
  "updatedAt": 0
}
```

`selectedResponseSource` 只能为 `generated_option` 或 `free_input`。自由输入沿用现有文本清理和长度限制，清理后为空时不能提交。

## 开场生成契约

开场请求读取冻结的试镜上下文与最终结果，包括：

- 担当偶像与制作人信息。
- 第一轮企划目标和角色命题。
- 最终分数、第一名结果和已结算奖励。
- `highlight`、`weakness`、`payoffSummary` 与 `resultSummary`。
- 主要训练成果、公开营业成果和关系回声。
- 前四段已经发生的事实摘要。

AI 输出独立标签中的 JSON，包含：

- `story`：可直接进入普通 VN 播放器的 `<dialogue>` 与 `<narration>`。
- `options`：恰好三个制作人回应文本。

开场固定发生在试镜会场后台候场区。偶像在排名公布后离开舞台，主动找到一直等待的制作人，表现符合其人设的第一反应，并自然停在等待制作人回应的位置。

三个动态选项必须语义有区分，分别覆盖：

1. 肯定本轮成果或直接表达认可。
2. 冷静复盘本场短板并指向下一轮。
3. 贴近两人当前关系与偶像性格的个性化回应。

选项不得修改比赛事实，不得许诺未确定奖励，也不得引入新的营业、训练或临时事件。自由输入由前端作为第四个入口提供，不要求 AI 输出第四项。

## 收尾生成契约

收尾请求在开场上下文基础上增加玩家最终回应，并明确其来源。AI 必须把玩家回应作为制作人的真实表达理解，而不是把它复述为系统选项或评价其选择质量。

收尾内容必须：

- 写出偶像对该回应的角色化反应。
- 自然承接本场 `highlight` 和已经兑现的培养成果。
- 承认 `weakness` 仍未完全解决，并将其作为下一轮的培养起点。
- 明确第一轮已经结束且两人会继续前进。
- 使用偶像的动作或台词结束，不再提出需要玩家处理的新问题。

AI 不得修改排名、分数、粉丝、属性、奖励或晋级结果，不得突然加入其他角色，不得时间跳跃到下一轮，不得开始新的营业或训练，也不得生成第二轮选择。

收尾输出独立标签中的 JSON，包含：

- `story`：完整、可播放并自然结束的 VN 正文。
- `recapSummary`：供状态恢复和后续轮次引用的简短客观摘要。

## 前端交互

试镜结果卡继续展示第一名、最终分数和实际奖励。玩家点击确认后，前端先应用奖励并保存，再进入复盘开场生成状态。

复盘沿用普通 VN 对话界面。开场播放结束后显示三个动态选项与自由输入。提交回应后锁定选择，隐藏选项并显示生成状态；收尾 VN 播放到最后一页时直接标记 `completed`，随后隐藏试镜 HUD、清理临时请求状态并返回 N.I.A 主界面，不再增加一次额外确认点击。

复盘不新增专用复杂界面。首版背景使用试镜会场后台候场区资源；专用背景尚未提供时，可临时复用试镜背景的暗化版本，但场景文本仍固定为后台候场区。

## 错误恢复

- 开场请求失败：保留已结算奖励和试镜结果，进入 `retryable_failed`，只重试开场。
- 开场已生成、等待选择时刷新：恢复已保存的开场与三个选项，不重复请求。
- 收尾请求失败：保留玩家已经冻结的回应，只重试收尾。
- 收尾已经生成、播放中刷新：恢复收尾 VN，不回到选项阶段。
- 重复确认试镜结果：由 `progressionApplied` 阻止再次增加粉丝或属性。
- 重复完成复盘：由 `postAudition.status === "completed"` 阻止再次推进。
- 请求身份不匹配或过期回复：拒绝应用，并保持当前可恢复状态。

数据库不参与复盘状态机的正确性。后续可将 `recapSummary` 作为纪要或关系更新的数据来源，但数据库不可阻塞奖励、选项或剧情完成。

## 测试范围

核心测试覆盖：

- `postAudition` 旧存档兼容与状态规范化。
- 合法状态迁移和非法重复操作。
- 开场必须返回完整 VN 正文与恰好三个非空选项。
- 收尾必须读取已经冻结的生成选项或自由输入。
- 空自由输入不能提交。
- 开场和收尾的请求身份隔离。
- 两个生成阶段各自的中断恢复与精准重试。
- 奖励在复盘前只应用一次，任何复盘重试都不能重复结算。
- 复盘未完成时不能把第一轮显示为完整结束。
- 收尾播放完成后返回 N.I.A 主界面并标记 `completed`。
- AI 输出不能覆盖排名、奖励或属性。

流程测试同时确认现有四段排名轨迹、第一名晋级、固定奖励和 N.I.A 双倍训练不受影响。

## 首版范围

首版只为第一轮试镜接入一次赛后复盘。第二轮与最终轮可复用同一子状态结构，但它们的专属叙事职责、奖励和背景不在本次实现范围内。
