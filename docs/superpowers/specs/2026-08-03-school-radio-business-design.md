# 《初星放送部》营业设计

## 目标

将真诚优主持的《初星放送部》设计为早期可选的独立节目营业。它是校园广播，不归入电视综艺节目池，但使用与其他营业一致的四段状态机、制作人临场介入和一次性结算规则。

## 已确定的界面方案

- 布局：A，正面演播室。
- 制作人介入：A1，第三段从画面下方升起桌边提示卡。
- 台词呈现：T1，广播字幕台。
- 正常播出时角色画面保持稳定，底部一次显示当前一句台词。
- 历史台词放入可展开抽屉，不持续占用主要画面。
- 轻量状态转场：待机、ON AIR、等待制作人指示、继续播出、已结束。

## 节目定位

节目类型使用独立的 `school_radio`，不复用电视综艺的节目池。

固定信息：

- 节目名称：《初星放送部》
- 主持人：真诚优
- 嘉宾：当前担当偶像
- 本期副标题：根据制作人企划目标生成
- 首秀门槛：无

首秀在早期排期中优先出现，但不是强制教学关卡。玩家可以跳过；完成首秀后解锁真诚优相关剧情和后续普通广播邀约。

## 制作人工作绑定

广播营业必须由三分之一天的制作人工作“广播部企划”准备。

该工作负责：

- 确定本期嘉宾。
- 确定访谈重点。
- 确定希望观众记住的核心印象。

工作产物 `radio_plan` 至少包含：`business_id`、节目主题、企划目标、主持人、嘉宾和访谈重点。工作不生成正文；正文只在广播营业中生成。

没有对应的 `radio_plan` 时，广播入口显示“尚未完成广播部企划”。广播营业读取同一份计划，四段内容不得脱离计划目标。

## 四段流程

### 第一段：嘉宾入场

真诚优介绍本期节目、嘉宾和主题，建立校园广播的轻松氛围。AI负责具体台词、动作、演播室反应和偶像表现，不提出需要玩家处理的问题。

### 第二段：主题访谈

围绕 `radio_plan` 的企划目标展开访谈。真诚优根据嘉宾回答自然追问，偶像通过性格化反应呈现企划想要塑造的印象。该段可以有小幅偏题，但必须回到本期主题。

### 第三段：听众来信

AI生成一封与企划目标或嘉宾性格有关的校园听众来信，形成唯一的计划外话题。内容必须具体、能由制作人提示影响，并在输出末尾停在“等待制作人指示”。

前端随后显示三个预设提示和一个自由输入。玩家只能介入一次；已提交的指示原文完整传入第四段。

### 第四段：回应与收播

AI根据制作人指示写出主持人与嘉宾如何接住听众来信、现场如何反应以及节目高光。必须在本段完成回应、总结和自然收播，不得提出新的问题、选项或悬念。

## AI 与前端边界

前端固定传入：

- 当前 `business_id` 和同一场广播的基础资料。
- 主持人、嘉宾、节目主题和 `radio_plan`。
- 当前段落编号及该段职责。
- 第三段必须停止等待指示。
- 第四段必须完整收尾。

AI负责：

- 具体互动台词。
- 日综式字幕、演播室反应和镜头化动作描写。
- 符合偶像性格的表现。
- 听众来信的具体形态。
- 偶像如何理解制作人指示并转化为节目高光。
- 最终观众反馈、公众印象变化和后续伏笔。

## 输出协议

广播使用独立的 `<NIA_RADIO>{JSON}</NIA_RADIO>` 协议，不套用普通 Galgame 的正文标签，也不复用直播或电视综艺的世界书规则。

每段响应至少包含：

```json
{
  "businessId": "...",
  "segment": 1,
  "status": "continue",
  "lines": [
    { "speaker": "真诚优", "text": "...", "expression": "neutral" }
  ]
}
```

第三段增加 `listenerLetter`、`problem` 和恰好三个 `options`，并使用 `status: "awaiting_producer"`。第四段增加 `highlight`、`audienceResponse`、`impressionChange`、`followupHook` 和 `resultSummary`，并使用 `status: "ended"`。

## 持久化与结算

前端保存当前段落、已播放台词、听众来信、预设提示和玩家指示，以便退出后恢复广播现场。

第四段结束后使用 `business_id` 和完成标记进行幂等结算。营业履历、粉丝变化和印象更新只能发生一次。数据库是体验增强层：数据库不可用时，广播仍应完成播放和基础结算；数据库恢复后可以补写履历，但不得重复增加收益。

## 设计检查结论

- 节目身份与电视综艺明确分离。
- 制作人工作负责准备，广播营业负责执行。
- 四段职责、第三段暂停和第四段收尾没有冲突。
- T1 的单句字幕不会遮挡主要角色画面。
- A1 的提示卡不会离开广播现场，也不会改变页面上下文。
- AI 动态内容受 `radio_plan`、段落职责和独立输出协议约束。
