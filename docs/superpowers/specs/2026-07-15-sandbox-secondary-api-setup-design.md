# 沙盒启动次 API 设置页设计

## 目标

在沙盒模式提交制作人档案后、开始担当邀请剧情前，增加一个次 API 设置步骤，让玩家在进入沙盒世界前完成公共世界生成配置，同时允许跳过。

育成模式启动流程保持不变。

## 启动顺序

沙盒模式的新顺序为：

`选择担当候选 → 填写制作人档案 → 设置次 API → 开始担当邀请剧情`

提交制作人档案时仍保存制作人资料，但不再立即调用 `startSandboxInviteStory()`。前端改为显示启动专用的次 API 面板；玩家保存或跳过后，再进入现有邀请剧情。

由于现有 `selectedIdol` 只是页面内存变量，进入新步骤时同时在 `state.sandbox` 保存：

- `apiSetupPending: true`
- `pendingIdol: <当前候选偶像>`

这样在次 API 页面刷新后仍能恢复同一启动步骤和候选偶像。保存继续或暂不填写后清除这两个 pending 字段，再调用原有邀请流程。

## 页面内容

次 API 面板沿用担当选择和制作人档案所在的启动页面布局，包含：

- 启用次 API 开关。
- 接口地址输入框。
- 模型名称输入框。
- API Key 密码输入框。
- 当前配置或连接测试状态。
- `测试连接`按钮。
- `暂不填写`按钮。
- `保存并继续`主按钮。

页面不新增 provider、temperature 或 max tokens 控件。

## 配置复用

启动页与手机“初星世界引擎”高级设置读写同一份配置：

- `state.tasks.secondaryApi.enabled`
- `state.tasks.secondaryApi.baseUrl`
- `state.tasks.secondaryApi.model`
- 现有浏览器本地 API Key 存储

打开启动页时调用现有配置读取逻辑进行预填。API Key 不写入普通存档，继续只保存在浏览器本地。

## 操作行为

### 测试连接

点击后先保存当前表单值，再复用现有 `runSecondaryApiTest()` 请求通道。测试允许在启用开关关闭时执行，只要求接口地址和模型已填写。

测试成功或失败都更新启动页状态，并保留现有 toast 与调试记录。测试结果不阻止进入沙盒。

### 保存并继续

保存当前启用状态、地址、模型和 API Key，然后进入原有沙盒邀请剧情。

即使配置不完整或连接测试失败，也允许继续。运行时继续由 `isSecondaryApiConfigured()` 决定使用次 API 或静态世界池。

### 暂不填写

只将 `enabled` 保存为 `false`，保留已存在或当前填写的地址、模型和浏览器本地 API Key，然后进入原有沙盒邀请剧情。后续可在手机世界引擎设置中重新启用。

## 状态与返回

- 新面板只在 `launchMode === "sandbox"` 且 `state.sandbox.apiSetupPending === true` 的启动阶段显示。
- 刷新或恢复时通过 `state.sandbox.pendingIdol` 恢复启动步骤；次 API 仍以现有配置为准，不创建第二套配置状态。
- 新面板不解锁手机，也不提前触发每日世界生成、Director 或 Storyteller。
- 启动页保存和测试操作不得开始邀请剧情；只有“保存并继续”或“暂不填写”可以继续。

## 测试

自动测试覆盖：

1. 启动页包含独立次 API 面板和完整控件。
2. 沙盒制作人档案提交后打开次 API 面板，而不是立即开始邀请剧情。
3. 待设置步骤与候选偶像可在刷新后恢复。
4. 育成模式仍直接进入原有开场流程。
5. 面板从现有配置与本地 Key 预填。
6. 测试连接先保存表单并复用现有测试函数。
7. 保存并继续写入配置、清除 pending 状态并开始邀请剧情。
8. 测试失败或配置不完整不阻止继续。
9. 暂不填写关闭启用状态，但不清空地址、模型或 Key。
