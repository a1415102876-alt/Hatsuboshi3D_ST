# N.I.A 5000 粉丝强制好感剧情设计

## 目标

为花海咲季的 N.I.A 路线增加一个按粉丝量触发的强制剧情里程碑。当 N.I.A 粉丝数首次从 5000 以下增长到 5000 或以上时，当前结算先正常完成，随后立即进入专属 VN 剧情。玩家必须看完剧情，才能继续 N.I.A 的训练、营业、制作人工作或试镜流程。

该事件只承担叙事职责，不增加好感度、粉丝、属性或其他数值，也不额外推进日期、时段或计划行动。

## 适用范围

- 首版只为担当偶像花海咲季启用。
- 事件 ID 固定为 `nia-saki-fans-5000`。
- 触发阈值固定为 5000 N.I.A 粉丝。
- 数据库存取保持可选，数据库失败不能阻塞事件。
- 不改变“初”路线的 `affinity`、好感度 20/40/60/80/100 事件和事件日逻辑。
- 不改变既有粉丝奖励、训练收益或试镜奖励。

## 状态结构

在持久化的 `state.nia` 中增加独立的粉丝里程碑事件状态，不复用 `state.affinity.pending`：

```js
fanMilestoneEvent: {
  eventId: "nia-saki-fans-5000",
  threshold: 5000,
  status: "idle",
  story: "",
  activeRequest: null,
  lastError: "",
  triggeredAtFans: 0,
  completedAt: 0
}
```

允许的 `status`：

- `idle`：尚未达到条件。
- `pending`：粉丝结算已跨过阈值，等待开始生成。
- `generating`：主 API 正在生成剧情。
- `playing`：剧情已生成，正在 VN 中播放。
- `retryable_failed`：生成中断或回复格式错误，只允许重试。
- `completed`：剧情已完整播放，永久不再触发。

旧存档缺少该字段时规范化为 `idle`。如果旧存档加载时已经拥有 5000 或更多粉丝但事件从未完成，则补记为 `pending`，在恢复 N.I.A 前强制触发。

## 触发与结算顺序

所有会增加 N.I.A 粉丝的结算入口继续使用原有奖励逻辑，包括制作人工作、网络直播、校园广播和第一轮试镜。每次写入新粉丝总数后，统一调用里程碑检查函数，而不是在各入口复制判断。

触发条件同时满足时，把事件从 `idle` 切换为 `pending`：

1. 当前路线是正式 N.I.A。
2. 当前担当偶像是花海咲季。
3. 事件尚未完成。
4. 结算后的 N.I.A 粉丝数大于或等于 5000。

当前活动的奖励、营业履历、行动进度和一次性结算标记必须先保存。里程碑事件只在这些原结算成功后接管界面，因此重试剧情不会重复执行原活动奖励。

## 强制阻塞

当事件处于 `pending`、`generating`、`playing` 或 `retryable_failed` 时：

- N.I.A 主界面不提供下一项行动。
- 当前营业、广播或试镜专用界面在完成自身结算后关闭。
- 前端只显示事件 VN、生成等待或重试界面。
- 关闭按钮不能绕过未完成剧情。
- 生成失败时只允许重试同一事件。
- 页面刷新后优先恢复该事件，再恢复普通 N.I.A 界面和其他可继续流程。

剧情播放到最后并由玩家完成关闭后，状态切换为 `completed`，清理请求与临时 VN 状态，再恢复 N.I.A 主界面。完成操作必须幂等。

## AI 输出契约

使用独立的主 API 请求和标签：

```text
<NIA_FAN_MILESTONE_EVENT>
{
  "schemaVersion": 1,
  "eventId": "nia-saki-fans-5000",
  "story": "<narration>...</narration><dialogue char=\"花海咲季\">...</dialogue>"
}
</NIA_FAN_MILESTONE_EVENT>
```

解析器只接受最后一个完整、事件 ID 匹配且 `story` 非空的标签块。标签外的思考、说明和其他文本一律忽略。

`story` 内只允许普通 VN 使用的 `<dialogue>` 与 `<narration>`。本事件没有选项，不接受或应用 `fanGain`、`affinityGain`、属性变化、时间推进、排名变化、营业结算或数据库写入指令。

## 剧情种子

提示词以 `E:/GKMS/hnms/好感剧情/gemini-code-1782773784906.txt` 为剧情种子，并要求 AI 保留以下叙事节拍：

1. 咲季发现粉丝和投票稳步增加，迅速得意忘形。
2. 制作人透露已经录下她欢喜若狂的样子，咲季慌张确认自己有没有说怪话。
3. 玩笑结束后，咲季主动恢复认真态度，指出当前排名仍不足以松懈。
4. 制作人提出通过持续偶像活动，让观众认识真实的咲季。
5. 佑芽带着自己的拉票成果出现，姐妹比较排名后发现并列。
6. 姐妹约定最终在 N.I.A FINALE 正面对决。
7. 制作人提醒咲季不能轻视妹妹以外的偶像，咲季承认问题并重新确认努力目标。

AI 可以自然改写台词、补充动作和场景衔接，但不能改变人物关系、比赛目标和事件结论。场景必须保持为 N.I.A 育成期间的校内或制作人工作区域，不创建新的营业、训练或突发危机。

## 恢复与错误处理

- `pending`：立即尝试生成剧情。
- `generating`：刷新后转为 `retryable_failed`，避免重复占用旧请求。
- `playing`：直接重播已保存的 `story`，不再次请求 API。
- `retryable_failed`：保留错误信息与事件身份，只重试剧情生成。
- `completed`：不拦截任何流程。

主模型通道被占用、宿主不可用、限流或回复格式错误时，必须释放本事件持有的通道租约。事件状态保留为可重试，原活动奖励和粉丝总数保持不变。

## 测试范围

- 旧存档状态规范化与 5000 粉丝补触发。
- 4999 到 5000 触发，5000 以上重复结算不重复触发。
- 非咲季担当和非 N.I.A 路线不触发。
- 所有 N.I.A 粉丝来源结算后都经过统一检查。
- 原奖励先保存，事件失败与重试不重复奖励。
- 生成中刷新变为可重试；播放中刷新重播保存剧情。
- 严格标签解析，忽略标签外思考和越权数值字段。
- VN 完成前无法返回或执行下一步，完成后正常恢复 N.I.A。
- 完成操作与事件触发均保持幂等。
