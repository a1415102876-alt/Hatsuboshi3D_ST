# 校内舞台 First Live 开始时间修正设计

## 问题

当前实现把 `19:00` 解释为最早开放时间：早于 `19:00` 时按钮禁用，确认挑战时返回 `too_early`。这与目标规则相反。

## 目标规则

- 每日地图开放后即可挑战 First Live。
- `19:00` 是最晚开始时间，不是最早开放时间。
- `19:00` 整仍可开始挑战。
- `19:01` 起不可开始挑战。
- First Live 开始后的时间推进继续沿用现有日终封顶规则。

## 实现

建立一个统一的 First Live 开始时间判定，以当前 `clockMinutes` 是否不晚于 `19:00` 为准。

地图按钮、设施状态文案和最终确认入口共用该判定：

- 可挑战时显示“举办 First Live”或“可挑战”。
- 超过 `19:00` 后禁用入口并显示“今日挑战时间已结束”。
- 最终确认返回明确的 `too_late` 原因，不再使用 `too_early`。

## 保持不变

- 三项属性贡献率与成功率计算。
- 单次随机判定及冻结结果。
- 180 分钟行动时长和现有日终封顶。
- 失败冷却、完成状态、Harness ownership、Recovery 与叙事流程。

## 测试

增加边界测试，至少覆盖：

- 上午时间可挑战。
- `19:00` 可挑战。
- `19:01` 不可挑战。
- 地图按钮与最终确认使用同一时间判定。

测试先在当前“19:00 后开放”实现上失败，再进行最小修复。
