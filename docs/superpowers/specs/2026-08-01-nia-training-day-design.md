# NIA 正式育成：训练日界面设计

## 目标

NIA 第一轮企划完成并经过亚纱里老师评价、完善后，直接进入现有正式育成界面的 NIA 变体。首版不增加额外过场，优先建立可继续扩展的正式训练日入口和 NIA 专属 HUD。

## 复用边界

- 复用现有育成模式的场景、人物、行动区、状态渲染和 Harness 体系，不复制第二套训练页面。
- 由正式模式状态判断是否启用 NIA 变体；普通育成模式和沙盒模式的现有表现保持不变。
- NIA 训练行动按照已确认企划的顺序推进。首版进入训练日时只开放当前企划行动，不提供脱离企划的自由行动。
- 企划确认后直接进入训练日；过场动画留作后续独立功能。

## 右上角审查基准

现有“审查基准”卡片扩展为四项：

1. Vocal：使用 `UI/Vo_Mini.png`。
2. Dance：使用 `UI/Da_Mini.png`。
3. Visual：使用 `UI/Vi_mini.png`。
4. 粉丝数：使用用户提供的简笔橙色星形资源。

四个图标放入相同尺寸的容器，通过 `object-fit: contain` 统一视觉占位；数值继续右对齐。卡片只在 NIA 状态增加粉丝项，非 NIA 状态保留原有三项结构。

## 粉丝进度栏

在审查基准卡片下方增加独立的 NIA 粉丝进度组件：

- 左侧使用用户提供的精细橙黄色星章资源。
- 中间为圆角半透明深灰色轨道。
- 内层橙色进度条随当前粉丝数从左向右填充。
- 当前粉丝数显示在轨道下方，使用千位分隔格式。
- 右侧复用项目已有的 E、D、C、B、A、S 字母评价视觉与映射规则。
- 首版不设计粉丝专属评级算法；直接接入现有评价规则。后续可在不改组件结构的前提下替换映射函数。

进度宽度需要限制在 0% 到 100%，避免数据越界破坏布局。粉丝数、目标值和评级均来自正式 NIA 状态，不写死在 DOM 中。

## 状态与流程

- NIA 正式状态增加当前粉丝数和粉丝审查目标；初始值由第一轮企划结果初始化。
- 亚纱里老师完善后的企划确认完成时，写入 NIA 训练日所需状态并切换到现有育成视图。
- 训练日渲染器根据模式增加 NIA 根类或数据属性，控制审查基准第四项、粉丝进度栏和企划行动限制。
- 粉丝变化后统一刷新数值、进度填充和字母评级，避免多个组件各自计算。

## 资源处理

- 精细星章和简笔星形分别保存为语义明确的 NIA UI 资源，不引用临时剪贴板路径。
- Vo、Da、Vi 直接复用项目 `UI` 目录已有 Mini 图。
- NIA 企划行动中的“营业”使用项目已有的 `UI/Business.png`。
- 所有图标保持原始宽高比，不使用拉伸填满。

## 验收标准

- 完成第一轮企划流程后可直接进入现有育成界面的 NIA 训练日。
- NIA 审查基准显示四个尺寸一致的图标和对应数值。
- 审查基准下方显示星章、灰色轨道、橙色填充、当前粉丝数及现有字母评级。
- 粉丝数变化会同步更新进度条和评级。
- 当前行动遵循企划顺序，不出现自由训练选项。
- “营业”行动显示 `UI/Business.png`，并与其他行动图标使用一致的尺寸规则。
- 普通育成与沙盒模式的审查基准、行动和流程不发生回归。
- 完成实现后统一运行现有自动化测试，并进行一次 NIA 流程与界面检查。
