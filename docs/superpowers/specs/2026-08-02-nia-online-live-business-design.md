# N.I.A 网络直播营业界面设计

## 目标

将“网上直播”从通用 VN 营业事件改造成完整的直播专用界面。整场营业由 AI 分四段连续生成，玩家只在关键问题出现时以制作人身份介入。界面需要同时体现偶像表现、观众即时反应、直播趋势和企划成果，并保持剧情连续性。

本设计只覆盖网上直播。电视综艺与线下活动继续使用现有营业流程，后续另行设计专用界面。

本设计取代此前“网上直播继续使用通用 VN 播放器”的实现方向；后续实施计划必须以四段式直播专用界面为准。

## 核心体验

玩家观看担当偶像完成一场真实推进的网络直播，而不是阅读一段事后描述。偶像的台词、动作、弹幕和状态变化按时间顺序播放。第三段出现与偶像性格、前文和营业企划相关的关键问题，玩家通过导播式指示帮助她解决。第四段自然收播，并在保留最后画面与弹幕的情况下展开结算。

## 界面结构

采用“学马仕式直播控制台”横向布局：

- 左侧约 68% 为直播画面，使用直播场景背景、偶像立绘和字幕式台词/动作。
- 右侧约 32% 为实时弹幕，评论按播放节奏逐条滚入。
- 直播画面左上显示 `LIVE` 和当前段数，例如 `2 / 4`。
- 底部状态栏持续显示当前在线人数、直播热度和舆论压力。
- 最底部话题栏显示当前直播话题、生成状态或下一步操作。
- 新增粉丝数不在直播过程中实时显示，只在收播结算时揭晓。

在第三段的关键问题出现后，底部从直播画面区域升起“制作人指示”抽屉。弹幕区保持可见。抽屉包含当前问题、三个 AI 生成的处理方案和一个自由输入入口。提交后抽屉收起，进入第四段生成。

## 四段流程

### 第一段：开场

偶像打招呼并说明直播主题，建立第一印象。AI 生成开场表现、第一批弹幕和初始趋势。本段播放完毕后出现“继续直播”。

### 第二段：内容展开

AI 承接第一段，围绕本轮企划形象展开主要内容。观众反应开始分化，并显现本场潜在风险。本段播放完毕后出现“继续直播”。

### 第三段：突发状况

AI 必须依据前两段内容、偶像性格、营业企划和已有风险制造一个具体问题。问题不能是无关随机事故，也不能直接结束直播。播放到问题点后停止推进，打开制作人指示抽屉。

### 第四段：处理与收播

AI 严格承接玩家选择或自由方案，描写偶像如何执行、弹幕如何回应，并在当前回复内完成自然收播。不得继续制造需要下一次选择的新悬念。播放结束后进入结算。

## AI 返回协议

每段返回一个结构化直播段落：

```text
schemaVersion
businessId
segmentIndex
topic
beats[]
comments[]
audienceTrend
heatTrend
pressureTrend
continuitySummary
```

`beats[]` 按播放顺序记录叙事、动作和台词。每项需要具有稳定标识、类型、说话人、文本和建议延迟。`comments[]` 记录弹幕文本、语气和应在第几个 beat 后出现。

趋势只允许使用受控枚举：

- `audienceTrend`: `down | flat | up | surge`
- `heatTrend`: `down | flat | up`
- `pressureTrend`: `relief | flat | up | spike`

第三段额外返回：

```text
incident
options[3]
```

第四段额外返回：

```text
resolution
imageMatch
bonusTier
bonusReason
closingSummary
```

`imageMatch` 使用 `off | partial | strong`，`bonusTier` 使用 `none | small | medium | large`。AI 负责内容与评价，不得直接输出最终粉丝数。

## 前端职责

- 校验 `businessId`、`segmentIndex` 和当前状态，拒绝跳段、旧回复和重复回复。
- 按顺序播放 `beats`，并在对应时机插入 `comments`。
- 将趋势枚举映射为受控的在线人数、热度和压力变化。
- 保存每段 `continuitySummary`，将已发生事实传入下一段提示词。
- 第三段只接受一次制作人方案，并将原文完整传入第四段。
- 根据营业基础粉丝、企划匹配度和 `bonusTier` 计算最终新增粉丝。
- 使用唯一营业编号保证第四段只能结算一次。

## 播放规则

每次 API 回复只生成一段。前端收到完整段落后才开始播放：

1. 逐条显示偶像台词与动作字幕。
2. 按 `triggerAfterBeatId` 和建议延迟滚入弹幕。
3. 在关键 beat 后平滑更新在线人数、热度和舆论压力。
4. 本段全部播放完毕后才开放下一步按钮。

生成下一段时保留现有直播画面和弹幕，只在话题栏显示“正在组织下一段直播内容”。不切回 VN 或 N.I.A 平板。

## 状态机

```text
ready
-> generating_1 -> playing_1 -> awaiting_continue_1
-> generating_2 -> playing_2 -> awaiting_continue_2
-> generating_3 -> playing_3 -> awaiting_producer_instruction
-> generating_4 -> playing_4 -> awaiting_settlement
-> settled
```

任一生成状态可以进入 `retryable_failed`，但必须保留最后一个完整段落和当前直播数值。重试只重发当前段。

## 结算呈现

第四段最后一句台词播放完毕后，直播画面降低饱和度并标记“直播已结束”。最后一批弹幕保留在右侧。结果面板从直播画面底部展开，显示：

- 新增粉丝。
- 企划形象强化程度。
- 舆论压力最终变化。
- 最高在线人数与最高热度。
- 额外加分等级及具体原因。
- 本场直播形成的公开印象。

玩家确认成果后才返回育成日程并推进营业日。

## 异常与恢复

- 生成中锁定推进按钮，防止重复请求。
- 回复格式不完整、段数错误、提前收播或留下新悬念时，不推进状态并允许重新生成本段。
- 刷新后从最后一个完整段落恢复，不恢复半段动画。
- 已完成的前三段不能因重试重新计算趋势。
- 第四段通过 `businessId` 和结算标识防止重复增加粉丝。
- 旧回复或不属于当前营业的回复必须忽略并回执为未接受。

## 与现有系统的边界

- 复用现有主 API 通道、请求租约和 SillyTavern 回复桥接。
- 复用现有偶像立绘解析与 R2 资源路径。
- 网络直播不再调用通用 VN 播放器。
- 现有 N.I.A 营业上下文继续提供本轮企划、偶像资料、制作人工作成果和基础粉丝。
- 网络直播完成后仍通过现有 N.I.A 训练状态推进 `actionIndex`。

## 验证范围

- 四段请求严格按序发送和接受。
- 第三段前不能提交制作人指示，第四段不能缺少玩家方案。
- 弹幕与 beat 顺序稳定，快速点击不能跳过结算锁。
- 格式错误重试不重复应用前三段数值。
- 刷新恢复后继续当前段，不回到 VN 或错误返回平板。
- 第四段重复回复只能结算一次。
- 桌面与窄屏均保持直播画面、弹幕和操作按钮可读且不重叠。
